# Поставување на сервер

Апликацијата досега работеше на лаптоп. Тоа има една цена што се виде на
03 и 04.10.2026: **машината не била будна во 11:00 и тие два дена воопшто
не се прочитани.** Нема враќање назад — ценовникот од вчера го нема повеќе
никаде.

Затоа апликацијата оди на машина што е секогаш вклучена.

## Што ти треба (ова е твое, не можам јас)

| | Што | Колку |
|---|---|---|
| 1 | VPS со 2 GB RAM и ~40 GB диск | 5–8 € месечно |
| 2 | Домејн | ~10 € годишно |

За големината: базата со **еден ден** податоци зафаќа 11,6 MB компримирана.
`current_price` не расте (се пребришува), `price_change` носи само промени.
40 GB е доволно за години, со резервните копии внатре.

Провајдер: Hetzner (CX22, ~4 €), DigitalOcean, Contabo — сеедно. Земи
Debian 12 или Ubuntu 24.04.

## Чекор 1 — домејнот да покажува на серверот

Во панелот на домејнот додади `A` запис кон IP-то на серверот. Провери:

```bash
dig +short marketchecker.mk
```

**Ова мора да е готово пред да стартуваш.** Caddy вади сертификат за
домејнот; ако не покажува на серверот, Let's Encrypt ќе одбие.

## Чекор 2 — Docker на серверот

```bash
ssh root@ip-на-серверот
curl -fsSL https://get.docker.com | sh
```

## Чекор 3 — кодот и тајните

```bash
git clone https://github.com/Darkosp/Marketcheker.git
cd Marketcheker
cp .env.example .env
```

Отвори го `.env` и смени ги **најмалку** овие:

```bash
# Генерирај ги со:
python3 -c "import secrets; print(secrets.token_urlsafe(48))"

SECRET_KEY=<генерираното>
POSTGRES_PASSWORD=<друго генерирано>
APP_ENV=production
APP_DOMAIN=marketchecker.mk
ACME_EMAIL=ti@primer.mk
```

Апликацијата **нема да стартува** ако `APP_ENV=production` а тајните се
примерните од `.env.example`. Тоа е намерно: тајна што стои во јавно репо
не е тајна, а сесија потпишана со неа може секој да ја фалсификува.

## Чекор 4 — пушти

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Што се случува по ред: базата станува, миграциите се вртат, и дури потоа
стартуваат апликацијата и распоредот. Новата верзија никогаш не зборува со
стара шема.

Провери:

```bash
docker compose -f docker-compose.prod.yml ps
curl -fsS https://marketchecker.mk/health
```

## Чекор 5 — првото читање

Распоредот чита секој ден во 11:00. Првото не го чекај:

```bash
docker compose -f docker-compose.prod.yml run --rm api python -m app.cli citaj
```

Трае околу два и пол часа. **`run --rm`, не `exec`** — еднаш го прекинав
читањето по два часа со `restart` на контејнерот во кој се вртеше.

## Што е поинаку од развојниот состав

| | Развој | Сервер |
|---|---|---|
| Код | жив од дискот, `--reload` | вграден во сликата |
| Postgres | изложен на портот 5434 | **не излегува воопшто** |
| Апликација | на 8000 | зад Caddy, не излегува |
| HTTPS | нема | автоматски, се обновува сам |
| Миграции | рачно | одделен чекор пред стартување |
| Резервни копии | нема | дневна, 14 дена |

## Резервните копии

Секој ден во `./backups`, 14 дена наназад. Враќање:

```bash
gunzip -c backups/marketchecker-2026-10-04.sql.gz \
  | docker compose -f docker-compose.prod.yml exec -T db \
    psql -U marketchecker -d marketchecker
```

**Ова не е копија надвор од серверот.** Ако дискот пропадне, пропаѓа и таа.
Кога ќе има шест месеци историја што вреди, истата датотека треба да се
носи и настрана — `rsync` на друга машина или S3. Дотогаш е доволно.

## Ново пуштање

```bash
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

Миграциите се вртат сами. Паузата е неколку секунди.

## Што НЕ е направено

- **Нема автоматско пуштање** од GitHub. Со еден сервер и едно `git pull`,
  CI/CD е повеќе работа отколку што враќа.
- **Нема надзор.** Ако читањето падне во 11:00, тоа го гледаш на
  `/sostojba`, не преку порака. Кога ќе почне да ти пречи, тоа е следното.
- **Нема `fail2ban`, нема firewall освен тоа што Docker го отвора.** На
  серверот се отворени 22, 80 и 443.
